# Spike results — MVP de-risking (2026-10-26)

Environment: CachyOS, Go 1.27.1, Node v26.7.0, Electron 42 at
`/usr/lib/electron42/electron` (bundled Node v24.19.0). The real Grok Bot package
is NOT installed, so the proprietary daemon itself could not be exercised; every
spike that needs "a Node-compatible runtime" was validated with `node` and/or the
Electron binary, which produce the identical wire behavior the daemon relies on.

Run it yourself:
    go test ./...                       # all unit + spike tests
    go test -race ./...                 # concurrency check (IPC reader goroutine)
    go build -o /tmp/groknode ./cmd/groknode
    /tmp/groknode checksum my-machine-id
    /tmp/groknode ipc-probe /usr/lib/electron42/electron <script.cjs> --run-as-node

## S2 — Node fork() IPC from a Go (non-Node) parent  ✅ PROVEN
Approach: `socketpair(AF_UNIX, SOCK_STREAM)`, pass the child end as fd 3 via
`exec.Cmd.ExtraFiles`, set `NODE_CHANNEL_FD=3` and `NODE_CHANNEL_SERIALIZATION=json`,
exchange newline-delimited JSON. Implemented in `internal/ipc`.

Result: a Go parent completes the full bootstrap handshake with both plain
`node` v26 and Electron-42-as-node. The child's `process.on('message')` receives
exactly `{"type":"sand-local-exec-file-key","key":null,"computerId":"<id>"}` and
`process.send(...)` back to Go decodes cleanly. Default `json` framing is correct;
no `advanced`/v8 serialization and no OS-handle (SCM_RIGHTS) passing was needed for
the bootstrap. Covered by `TestNodeIPCHandshake` and `TestElectronRunAsNodeHandshake`.

Still to confirm against the REAL daemon (needs the package installed): that the
daemon doesn't *later* send a message carrying a handle, and that it accepts the
bootstrap as-is. The transport is proven; only the daemon's own message vocabulary
remains unverified.

## S1 — Electron-as-node runs headless without a display server  ✅ PROVEN
`ELECTRON_RUN_AS_NODE=1` with `DISPLAY`, `WAYLAND_DISPLAY`, and `XDG_RUNTIME_DIR`
all stripped from the environment:
- `electron -e` runs and reports `display:null, wayland:null`, node v24.19.0.
- The full IPC handshake completes with `hasDisplay:false, hasWayland:false`.

Conclusion: no X11/Xvfb/Wayland server is required — `RUN_AS_NODE` skips Chromium
init. CAVEAT: the Electron *binary* still dynamically links GTK/X11/NSS `.so`
libraries, which must be present on disk (here, the electron42 package supplied
them). On a minimal server those libraries must be installed (or bundled in the
container image), but a running display is not needed. This exactly matches the
plan's §2 constraint #4.

## Checksum — JS 32-bit-shift-faithful port  ✅ PROVEN
`internal/protocol.Checksum` is validated against golden vectors generated by
running the ORIGINAL grokbot-headless JS `cursorChecksum` under Node (see
`checksum_test.go`). The uint32 + `shift % 32` + `&0xff` approach reproduces JS's
int32 shift wraparound byte-for-byte. `TestChecksumGolden` passes.

## Protocol client / credential mint  ✅ PROVEN (against fake backend)
`internal/protocol.Client` performs the daemon-credential mint and the
`IssueGrokBotUserComputerCredential` Connect-unary RPC in parallel and assembles
the descriptor. `TestMintDescriptor` runs it against an `httptest` fake backend and
asserts: exact auth header set (`authorization`, `x-cursor-checksum`,
`x-cursor-client-type: sand`, `x-sand-box-namespace: prod`, `x-ghost-mode`,
`x-request-id`), `connect-protocol-version: 1` on the RPC, and correct descriptor
assembly (credentials, expiry, accountScope, serverAuthoritative).

Unverified: real endpoint paths/response shapes at `api2.cursor.sh` (needs real
credentials). Shapes are taken verbatim from the reference client.

## S3 — package format / asar contents  ✅ DONE (real package: grok-bot-bin 0.75.8-1)
Installed via AUR at `/opt/Grok Bot/` (binary `grok-bot`, 220MB Electron). Key facts:
- Vendor Electron: **42.11.16** (Chrome 148).
- Daemon entry UNCHANGED from the reference: `/dist/local-exec-daemon/main.cjs`
  (3.77MB bundle) + `messages-worker.cjs`, inside `app.asar`.
- Native modules in `app.asar.unpacked/dist/deps/`: tree-sitter(+bash),
  sand-window-capture, sand-devicecheck, cursor-proclist,
  sand-card-text-recognition, sand-notification-settings. These are prebuilt
  against Electron 42's Node ABI -> the runtime MUST be ABI-compatible with
  Electron 42 (system node v26 will NOT load them).

## S4 — CRITICAL: official binary has `run_as_node` FUSED OFF  ⚠️ APPROACH-BREAKING
The reference project (tested on 0.30.0) runs the daemon via
`ELECTRON_RUN_AS_NODE=1 /opt/Grok Bot/grok-bot <daemon>`. On 0.75.8 that no
longer works. Electron fuse readout of `/opt/Grok Bot/grok-bot`:
- `run_as_node`: **DISABLED**  (ELECTRON_RUN_AS_NODE ignored)
- `enable_node_options_env`: DISABLED
- `enable_node_cli_inspect`: DISABLED
- `enable_embedded_asar_integrity`: ENABLED
- `only_load_app_from_asar`: ENABLED
Confirmed empirically: `ELECTRON_RUN_AS_NODE=1 grok-bot -e '<code>'` ignores the
code and boots the tray app instead. xAI hardened the desktop binary. The
original controller's launch strategy is DEAD on current builds.

## S5 — WORKAROUND VALIDATED: bring our own ABI-matched Electron runtime  ✅ PROVEN
Stock Electron ships with `run_as_node` ENABLED. This box already has
`/usr/lib/electron42/electron` v42.11.18 (same Electron 42 major = same Node ABI
as the vendor's 42.11.16). Running the REAL vendor daemon under it, headless
(DISPLAY/WAYLAND stripped), no credentials, isolated SAND_DATA_ROOT:

    groknode daemon-probe /usr/lib/electron42/electron \
        "/opt/Grok Bot/resources/app.asar/dist/local-exec-daemon/main.cjs" 0.75.8 12

Output:
    [daemon stdout] [sand-local-exec-daemon] started (pid ...); serving local exec over the gateway
    [daemon stdout] [sand-local-exec-daemon] desktop ownership lost, shutting down

Conclusions:
- Stock Electron 42 (open-source, redistributable) successfully loads and runs the
  proprietary daemon + its native modules, HEADLESS. This is the runtime strategy.
- Our Go IPC channel's newline-JSON `sand-local-exec-file-key` bootstrap is
  accepted by the REAL daemon (no framing/handshake errors).
- `desktop ownership lost` is the expected no-credential outcome: ownership is a
  backend-coordinated, per-machine concept (`ownershipPolicy`, `desktop
  coordinator`, `sand library store ownership check failed`), NOT a requirement
  for a local X session. With a valid minted descriptor the daemon claims
  ownership for its machineId and stays up. This is the first thing to confirm on
  the LXC via the full login+mint+run flow.

Architectural upshot: we do NOT need the 220MB official binary at runtime. The
container/host runtime = stock Electron 42 + a copy of the vendor's
`dist/local-exec-daemon/` and `app.asar.unpacked/dist/deps/` native modules. The
official binary's hardening fuses (asar integrity, only_load_app_from_asar) are
irrelevant to us because we never execute that binary.

## Still unverified (needs real OAuth creds on the LXC)
- Full `login -> mint descriptor -> run` flow holding ownership and staying up.
- Live `api2.cursor.sh` endpoint paths/response shapes on 0.75.8 (the reference
  shapes are from 0.30.0 and may have drifted — watch the mint/register RPCs).
- Whether any native module (e.g. sand-window-capture) eager-loads a display lib
  on the daemon's active code paths (it booted clean headless, so not at startup).

## Net assessment
Both make-or-break theories (Node IPC from Go; headless proprietary runtime) are
validated against the REAL daemon. One approach-breaking change was caught early
(S4 run_as_node fuse) and a clean workaround proven (S5 BYO Electron 42). Remaining
unknowns need only real credentials on the target box. Green light for the
supervisor/state/packaging build (PLAN.md phases 2–5) with the runtime strategy
revised to bundle stock Electron 42.
